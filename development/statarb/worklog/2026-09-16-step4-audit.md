## What the audit found

### Nine flags took values they should have refused

Two failed in the dangerous direction — the direction that makes a result look better than
it is.

**`deflated_sharpe.py --trial-sd -2`** exited 0. `expected_max_sharpe` returns zero for a
non-positive spread, so a negative value deflates against a benchmark of **zero** — which is
not deflating at all, reported as though the Sharpe had survived a deflation.

**`multiple_testing.py --bootstrap -5`** silently skipped the bootstrap. Zero means "skip"
and is documented; a negative number looked like a request for replicates and produced none,
so the verdict fell back to the weaker estimate without saying so.

The rest were noisier but no better:

| flag | was | now |
|---|---|---|
| `multiple_testing --effective-sample 0` | estimate quietly dropped | refused |
| `deflated_sharpe --sweep a,b` | uncaught traceback, exit 1 | refused, exit 2 |
| `overfit --entry-grid x,y` | uncaught traceback | refused |
| `overfit --holding-grid x` | uncaught traceback | refused |
| `overfit --holding-grid 0` | accepted, zero-bar holds | refused |
| `purged_cv --horizon -5` | exit 2, wrong explanation | refused, named |
| `purged_cv --embargo -5` | reached the internal guard | refused up front |

The `--horizon` one is worth spelling out. A negative horizon reversed the forward-return
slice and emptied the sample, after which the script reported *"gives 0 usable observations,
too few for 6 folds"*. True, and the wrong explanation — the fold count was fine.

Grid parsing now goes through `outcomes.parse_levels`, which already existed and already
produced the right message. Three scripts were each doing their own `float(v.split(","))`.

### One dead import

`purged_cv.py` imported the cost model and never used it. It works on prices alone, which is
correct — a leakage test has nothing to do with what a broker charges.

## The mutation test found two more, in the tests

Nineteen deliberate defects across the four scripts. The first run caught seventeen.

**A removed guard looked identical to a working one.** Deleting the negative-horizon check
left the run still exiting 2, because it fell through to the empty-sample error. The refusal
checks asserted the exit code and nothing else, so they passed on a broken build.

They now assert the exit code **and** that the message names the flag. Exit code alone is not
a test when two different failures share it.

**Nothing pinned the value of the expected maximum.** The deflation benchmark blends two
quantiles, `(1 − γ)Φ⁻¹(1 − 1/N) + γΦ⁻¹(1 − 1/(Ne))`. Dropping the second term leaves every
monotonicity check passing — more trials still raise it, a wider spread still raises it, it
is still never negative — while the benchmark comes out about 8% too low. A benchmark that
is too low deflates too little and lets more through.

Pinned now against figures derived by hand: 2.530603 at 100 trials, 3.255122 at 1,000, with
a structural check that the blend exceeds its lower quantile alone.

Both were failures of the tests rather than of the code, and both were the same shape as the
two found during the Step 3 audit: a check that passes for a reason other than the one it
claims.

## Verification

New: sixteen command-line refusals, each asserting the flag is named; the expected maximum
against derived values; and linear scaling in the trial spread.

## What did not change

The numbers. Every result from the previous session reproduces — `NUE~STLD` still deflates
from a probabilistic Sharpe of 80.5% to a deflated 3.5%, `RSG~WM` and `KEY~ZION` still show
probabilities of backtest overfitting of 77% and 67%. The audit fixed how the scripts behave
when given bad input, not what they say when given good input.
