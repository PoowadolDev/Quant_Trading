## What the audit found

### The command line accepted numbers that inverted the script

Five numeric flags had no validation. Three of them did not merely produce nonsense; they
reversed the meaning of the result.

**`sizing.py --confidence -3`** was the worst. The confidence parameter is the number of
standard errors subtracted from the estimated mean before sizing on it — the haircut that
stops a thin sample being sized as though it were thick. A negative value *adds* the
uncertainty back on, sizing up on precisely the evidence that is weakest. On `XLP~XLB` it
returned:

```
after a -3 s.e. haircut       12.97
after the 1x cap               1.00
SIZE 100,000 of gross exposure on 100,000 of equity
```

Full leverage on a pair that every other test in this project rejects. The verification
suite already caught this exact defect as a code mutation; it was reachable from the
command line the whole time.

**`sizing.py --equity -1000`** exited 0 and printed `SIZE -453 of gross exposure on -1,000
of equity`.

**`thresholds.py --min-edge -2`** would accept a trade earning less than it costs, which is
the one thing that gate exists to refuse.

Also unvalidated: `--max-leverage` below zero, `--min-reached` outside 0–1, `--min-trades`
below 1, `--max-overstatement` at or below zero, and `--entry-grid` given text instead of
numbers, which raised an uncaught traceback rather than a usage error.

All nine now refuse with exit 2 and a message that says what the value would have done.

### A flag that did nothing

`risk.py --max-drawdown-bps` was declared and documented, and `drawdown_breach` was written
and tested — but nothing ever called it. A user could set a drawdown limit and believe it
was protecting them.

The kill switch needs an equity curve, and an equity curve needs a replay with real costs,
which meant the book had to know a broker. Book entries now optionally carry one:

```bash
python risk.py --book XLP~XLB:index:etf,ALL~TRV:equity:equity
```

Given brokers, the book builds an equally weighted equity curve and applies the switch,
reporting the **first** bar past the limit rather than the worst — everything after that
date is a trade the rule says was never placed. Without brokers it says the switch was not
evaluated rather than passing silently.

On the two-pair book it fires on 1999-10-05 at −1,040 bps against a 1,000 limit.

### One definition, in two places, that disagreed

`signal_report.py` reported "no threshold pays" for `XLP~XLB` where `thresholds.py`
reported a floor at z = 1.50. Financing is signed the way brokers quote swap, so a debit is
negative and the cheaper of two directions is the **larger** signed value. The report took
the minimum, pricing the most expensive leg.

Fixed, but the fix left two implementations of the same choice. It is now one function,
`backtest.cheaper_direction`, used by both, and the two agree on every pair tested.

### Dead code

`--split` in `signal_report.py`, and unused imports of `pandas`, `outcomes` and `types`.
`sizing.py`'s docstring claimed its mean and deviation came "via `outcomes.py`" when it
reads the replay's trades directly; the docstring now says what the code does.

`--verbose` is declared and unused in every script in this project, Step 3 and earlier
alike. Left alone: it is a project-wide convention, not a Step 3 regression, and changing
it belongs in its own pass.

## Verification

The suite grew from 164 checks to 185. New groups:

- **the command line refuses bad numbers** — six subprocess checks, one per flag that
  previously produced a reversed or nonsensical result
- **book equity** — a curve is built only when every relationship has one, curves combine
  equally weighted, and the kill switch fires on a book that only falls
- **direction** — the cheaper side is the one that pays less, swapping which leg is
  expensive swaps the answer, and the same function decides it everywhere

**Mutation-tested at twenty defects, twenty caught.** The five new ones removed each guard
in turn and made book equity accept a missing curve. The direction mutation had been missed
on the previous run, because the checks exercised the cost functions but nothing exercised
the report's own choice — which is exactly the gap that let the bug ship. Moving the choice
into one function closed both the bug and the hole in the test.

## The skill

`.claude/skills/sizing/SKILL.md` covers all five scripts, with the evidence rather than the
instructions: the predicted-against-realised table across seven pairs, the completion-rate
table that explains it, the modelled floor losing 501 bps where the measured floor makes
3,414, and the sizing arithmetic that returns zero on all seven pairs including the three
that made money.

Cross-linked both ways. `statarb` now says its half-life and expected move are estimates
rather than outcomes; `tradingcosts` carries the financing-per-bar rule; `backtest` says a
net figure from the engine is not an edge; `relationship` points here for whether and how
much to trade.

Eleven rules, the load-bearing ones being: never quote the expected-move formula as a
payoff, never take a threshold from a grid's best cell, never size on gross returns, never
count positions as bets, and never charge 1.0 nights per bar outside crypto.

## Still true

No candidate. Seven pairs, seven rejections, on three independent tests each. The machinery
for Steps 0 to 3 is complete and verified at 418 checks, and what is missing is not code.
